# 分段回复

将 AstrBot 的完整回复按标点或自定义规则拆成多条消息，按配置的间隔逐段发送，让长句回复更接近日常聊天的节奏。

> [!NOTE]
>
> 本插件实现 AstrBot 原有分段回复功能，并增加额外增强能力。

## 功能概览

- **两种分段方式**：使用内置或自定义正则表达式，或按分段词列表拆分。
- **两种发送间隔**：随机间隔，或根据文本长度计算的对数间隔。
- **首段立即发送**：默认跳过首段等待，也可让首段使用相同的间隔规则。
- **省略号拆分优化**：结合上下文判断是否在 `…` 后分段，避免仅有省略号、标点相邻等情况被误拆。
- **新消息加速**：同一会话有新的 LLM 请求等待时，可缩短当前回复的剩余发送间隔。
- **内容清理**：分段后按正则移除指定内容，默认移除中文句号 `。`。

## 安装与启用

### 环境要求

- AstrBot 版本：`>=4.27,<5`，以 `metadata.yaml` 声明为准。
- 无额外运行依赖，使用 AstrBot API 和 Python 标准库。

### 启用步骤

1. 将本仓库放入 `AstrBot/data/plugins/astrbot_plugin_segmented_reply`。
2. 在 AstrBot 插件管理中加载并启用插件。
3. 关闭 AstrBot 全局原生分段回复：`platform_settings.segmented_reply.enable`。
4. 按需调整插件配置，保存后重启 AstrBot。

插件启用后即参与分段处理，无需额外的功能开关；需要暂停时，在插件管理中停用本插件。

> **原生分段回复优先。** 如果 AstrBot 全局原生开关仍开启，本插件会跳过处理，避免重复切分和等待时间叠加。

使用默认分段规则，回复：

```text
你好。今天过得怎么样？我们聊聊吧！
```

会依次发送为：

```text
你好
今天过得怎么样？
我们聊聊吧！
```

首段不额外等待，后续每段默认等待 `1.5～3.5` 秒。这里的“立即发送”只表示跳过插件的延迟，不包含模型生成、核心处理或网络发送耗时。

## 配置说明

### 增强设置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `acceleration_ratio` | `1.0` | 新消息触发加速后的等待比例，范围 `0～1`；`1` 不加速，`0` 取消剩余人为等待。 |
| `ellipsis_optimization` | `true` | 在正则模式下，按上下文进一步拆分省略号。 |
| `skip_first_delay` | `true` | 跳过首个发送组件的等待；关闭后首段也会等待。 |

### 分段回复设置（`settings`）

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `only_llm_result` | `true` | 仅处理被 AstrBot 标记为模型结果的回复；关闭后也处理符合条件的普通结果。 |
| `interval_method` | `"random"` | 间隔算法：`random` 为随机间隔，`log` 为对数间隔。 |
| `interval` | `"1.5,3.5"` | 随机间隔的秒数范围，填写两个英文逗号分隔的数值，仅随机模式使用。 |
| `log_base` | `2.6` | 对数间隔的基数，必须大于 `0` 且不等于 `1`，仅对数模式使用。 |
| `words_count_threshold` | `300` | 单条 `Plain` 文本超过该字符数时保持原样，不拆分也不清理。 |
| `split_mode` | `"regex"` | 分段方式：`regex` 为正则表达式，`words` 为分段词列表。 |
| `regex` | 内置标点规则 | 匹配完整文本段的 Python 正则，仅正则模式使用。 |
| `split_words` | `["。", "？", "！", "~", "…"]` | 命中任一词时分段，并移除命中的分段词，仅分段词模式使用。 |
| `content_cleanup_rule` | `"。"` | 对每段执行 `re.sub(rule, "", text)`；设为 `""` 可关闭正则清理。 |

`words_count_threshold` 使用 Python `len(text)`，不是单词数、Token 数或每段长度上限。例如阈值为 `300` 时，长度恰好为 `300` 的文本仍会参与拆分，超过 `300` 才跳过。

### 配置示例

以下示例使用默认正则、随机间隔和首段立即发送，并在新消息触发加速时将等待缩短至原来的 `70%`。未列出的配置项使用默认值。

```json
{
  "settings": {
    "only_llm_result": true,
    "interval_method": "random",
    "interval": "1.5,3.5",
    "words_count_threshold": 300,
    "split_mode": "regex",
    "content_cleanup_rule": "。"
  },
  "acceleration_ratio": 0.7,
  "ellipsis_optimization": true,
  "skip_first_delay": true
}
```

手动配置时，`acceleration_ratio` 应与 `settings` 同级。

## 分段规则

### 正则模式

设置 `settings.split_mode` 为 `regex`。

默认规则按 `。`、`？`、`！`、`~` 拆分，保留段尾标点，再由清理规则处理。内置规则识别常见成对括号和引号，避免将其中的标点直接作为断点；这不等同于完整的 Markdown 或嵌套结构解析。

自定义 `settings.regex` 时，插件使用 `re.findall`，并开启 `re.DOTALL | re.MULTILINE`。表达式应匹配**完整文本段**，而不是只匹配分隔符。建议使用非捕获组 `(?:...)`，并覆盖末尾没有标点的文本，避免部分匹配导致内容遗漏。

例如，按换行分段并保留尾段，可填写：

```regex
[^\n]+(?:\n+|$)
```

### 省略号拆分优化

`ellipsis_optimization` 仅影响正则模式，对匹配到的文本段进一步处理 Unicode 省略号 `…`（包括连续的 `……`）。满足以下条件才会在省略号后拆分：

- 省略号前后都有字母或数字。
- 省略号前最近的非空白字符不是标点。
- 省略号不在识别到的成对括号或引号内部。

例如，在默认清理规则下：

| 原文 | 发送文本段 |
| --- | --- |
| `前文……后文。` | `前文……`、`后文` |
| `……正文。` | `……正文` |
| `正文，……内容。` | `正文，……内容` |
| `（123）……456。` | `（123）……456` |

关闭该开关后，默认正则不会因省略号拆分；如果自定义正则本身匹配省略号断点，关闭此开关不会撤销该匹配。

### 分段词模式

设置 `settings.split_mode` 为 `words`，在 `settings.split_words` 中填写分段词。分段词按字面文本匹配，不是正则表达式；匹配到的词会从段尾移除。

例如，设置 `split_words` 为 `["。", "！？"]`：

```text
输入：第一段。第二段！？尾巴
输出：第一段 / 第二段 / 尾巴
```

此模式不受 `ellipsis_optimization` 影响。若列表包含 `…`，即使关闭省略号优化，仍会按该分段词拆分。清空列表后不按分段词拆分，但仍会执行内容清理和首尾空白去除。

### 内容清理

拆分后，对每段执行 `content_cleanup_rule`，再去除首尾空白，忽略空段。正则清理作用于整段内容，而不仅是段尾。

- 保留标点：设为 `""`，关闭正则清理；首尾空白仍会去除。
- 移除中文句号、问号和叹号：设为 `[。？！]`。
- 分段词模式中已移除的分隔词，不会因关闭清理而恢复。

## 发送间隔与加速

### 随机间隔

`interval_method = "random"` 时，每次等待从 `interval` 指定范围中随机取值，单位为秒。例如 `"1.5,3.5"` 表示每次等待约 `1.5～3.5` 秒。

### 对数间隔

`interval_method = "log"` 时，文本段的等待时间在以下范围内随机取值：

```text
log(N + 1, log_base) ～ log(N + 1, log_base) + 0.5 秒
```

其中，全 ASCII 文本的 `N` 为按空白分隔的单词数；含非 ASCII 字符的文本，`N` 为字母和数字字符数。非文本组件使用 `1～1.75` 秒的随机间隔。

### 新消息触发加速

同一会话的新消息进入 LLM 会话锁等待前，插件会通知该会话正在发送的回复，按 `acceleration_ratio` 缩短当前剩余等待和后续分段间隔。并非任意收到的消息都会触发加速，触发点是 AstrBot 的 LLM 请求等待钩子。

以 `acceleration_ratio = 0.7` 为例：

- 当前等待还剩 `2` 秒，缩短为 `1.4` 秒。
- 后续某段原本等待 `3` 秒，改为等待 `2.1` 秒。
- 重复触发不会再次叠乘，不会从 `0.7` 变成 `0.49`。
- 加速只影响当前回复，不影响其他会话，也不延续到下一次回复。

`0` 表示取消剩余人为等待，不会取消尚未发送的内容；`1` 表示不加速。超出范围、布尔值或非有限数值会直接报错，错误信息为 `acceleration_ratio must be a finite number between 0 and 1`。

## 适用范围与限制

- **不处理流式结果**：流式输出和流式结束结果均跳过。
- **不处理指定平台**：`qq_official_webhook`、`weixin_official_account`、`dingtalk` 均跳过。
- **默认仅处理模型结果**：判断依据是 AstrBot 的模型结果标记，不保证只包含正常生成的正文；模型运行器错误结果也可能属于模型结果。
- **只拆分 `Plain` 文本**：非文本组件保留，发送时按组件依次发送；语音组件单独发送，引用与 `@` 跟随首个非语音组件。
- **核心仍参与后续处理**：回复前缀、引用、`@`、TTS、转图片和转发等仍由 AstrBot 核心处理。最终内容和顺序以所用 AstrBot 版本及平台行为为准。
